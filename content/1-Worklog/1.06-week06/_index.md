## Objectives

* Implement observability for cloud resources and deployed services.
* Configure CloudWatch dashboards, logs, metrics, and alarms.
* Use tracing and distributed monitoring to understand request flow.
* Review cost visibility and identify anomalies early.

## Suggested tasks

| Day | Task | Notes |
|-----|------|-------|
| 1 | Design CloudWatch dashboards for key resources | Focus on CPU, memory, network, and request latency |
| 2 | Centralize logs from EC2, ECS, or Lambda into CloudWatch Logs | Create log groups and retention policies |
| 3 | Add CloudWatch alarms for high error rates, latency, and budget thresholds | Integrate with SNS notifications |
| 4 | Enable AWS X-Ray or distributed tracing for service calls | Visualize request paths and performance bottlenecks |
| 5 | Review AWS Cost Explorer and set up anomaly detection | Compare actual spend against forecast |
| 6 | Document observability patterns and lessons learned | Capture runbook steps and follow-up actions |

## Key achievements

* Built reusable dashboards for infrastructure and application health.
* Centralized logs and created alerts for critical incidents.
* Implemented tracing and monitoring for better service visibility.
* Identified cost patterns and enabled anomaly detection.
